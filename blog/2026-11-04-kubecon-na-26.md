## Sessions at KubeCon

OpenFeature maintainers, contributors, and adopters are presenting four sessions this year:

---

### [How We Are Enabling Feature Flagging At Scale](https://events.linuxfoundation.org/kubecon-cloudnativecon-north-america/program/schedule/?id=1247684)

|              |                                          |
| ------------ | ---------------------------------------- |
| **Speakers** | Juan Bernal (CVS Health)                 |
| **Date**     | Wednesday, November 11                   |
| **Time**     | 14:20 - 14:50 MST                        |
| **Location** | Salt Palace, Level 1, Grand Ballroom ACE |

CVS Health's DevEx team needed feature flagging for a large engineering organization and found that the options were either expensive vendor platforms or limited home-grown tools.
Juan shares how they built a standardized, open source flagging platform on OpenFeature, how they collaborated with the project along the way, and their plans to bring that work to the open source community.

---

### [Hope Is Not a Rollout Strategy: Balancing (AI) Quality, Cost, and Risk Through Experimentation](https://events.linuxfoundation.org/kubecon-cloudnativecon-north-america/program/schedule/?id=1250076)

|              |                              |
| ------------ | ---------------------------- |
| **Speakers** | Todd Baert (Dynatrace)       |
| **Date**     | Thursday, November 12        |
| **Time**     | 11:50 - 12:20 MST            |
| **Location** | Salt Palace, Level 2, 255 EF |

Shipping AI features responsibly is an experimentation problem.
Todd covers the three axes of quality, cost, and risk, and walks through a reference loop using OpenFeature, flagd, and OpenTelemetry that you can build next sprint.

---

### [OpenFeature Update from the Maintainers](https://events.linuxfoundation.org/kubecon-cloudnativecon-north-america/program/schedule/?id=1289731)

|              |                                         |
| ------------ | --------------------------------------- |
| **Speakers** | Jonathan Norris, Todd Baert (Dynatrace) |
| **Date**     | Thursday, November 12                   |
| **Time**     | 13:50 - 14:20 MST                       |
| **Location** | Salt Palace, Level 2, 251 D-F           |

This year the project reached a major milestone: platforms like Cloudflare, Google Cloud, Dynatrace, and Datadog now build their feature flag products directly on OpenFeature.
We'll dig into what that means for adopters and the ecosystem, then cover the rest of what's new across the SDKs, flagd, and OFREP.
Bring your questions.

---

### [OpenFeature as a Control Plane for OpenTelemetry](https://events.linuxfoundation.org/kubecon-cloudnativecon-north-america/program/schedule/?id=1246551)

|              |                                                     |
| ------------ | --------------------------------------------------- |
| **Speakers** | Simon Schrottner (Flagsmith), Juliano Costa (Dash0) |
| **Date**     | Thursday, November 12                               |
| **Time**     | 15:30 - 16:00 MST                                   |
| **Location** | Hyatt Regency, Level 4, Regency Ballroom CD         |

What if telemetry verbosity could adapt automatically?
Simon and Juliano combine OpenTelemetry and OpenFeature to control instrumentation at runtime, switching between lightweight traces and deep diagnostic telemetry without redeploying, and show how OpenTelemetry semantic conventions can act as a standard control surface.

## What's New in OpenFeature

A lot has happened since [KubeCon EU 2026](/blog/kubecon-eu-2026-recap).
Our [mid-2026 update](/blog/openfeature-mid-2026-update) covers it in depth, but here are some of the highlights:

- **Platform-native feature flags**: Datadog, Vercel, Cloudflare, Google Cloud, Mixpanel, and Octopus Deploy all shipped feature flag services built on OpenFeature.
- **New vendors in the ecosystem**: ConfigDirector, Feat, Featureflip, Featurevisor, Pendo, Rollgate, Superposition, and Switchbox shipped their first OpenFeature providers.
- **Specification v0.9.0**: the largest specification release in over two years.
- **Isolated API instances**: SDKs such as [.NET](https://github.com/open-feature/dotnet-sdk/pull/740) and [Ruby](https://github.com/open-feature/ruby-sdk/pull/354) now support isolated API instances alongside the global singleton.
- **C++ SDK**: the new [C++ SDK](https://github.com/open-feature/cpp-sdk) continues to mature with regular releases.
- **OFREP server-sent events**: the [OFREP](https://github.com/open-feature/protocol) ADRs adding SSE support and updated caching behavior have been accepted.
